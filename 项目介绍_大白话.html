① 一句话版

"我搭了个文档图书馆——把 PDF、Word 扔进去，你问它问题，它不光回答你，还告诉你在哪本书哪一页找到的。"

② 总比喻：你的项目 = 一家图书馆

把整个系统想成图书馆，每个文件就是馆里的一个岗位。
岗位对应文件干嘛的
收书员loader.py收书：PDF/Word/TXT 都收，统一切成能读的纸
裁纸员splitter.py把一本厚书裁成一页页小卡片（每页约512字）
档案管理员ingest.py每张卡片抄一份送进档案柜，柜子记住每张"字面"和"意思"
档案柜chroma_data\ 文件夹
（背后是 chromadb 库，pip 装的）		存卡片的地方，能按"意思"和"关键词"两头找
检索员retriever.py你问"啥是RAG"，它同时按意思找 + 按关键词找，两路结果合并
精筛员reranker.py找到20张先粗筛，再精排挑最像的5张
抄写员generator.py把5张卡片抄给 DeepSeek，让它照着卡片写答案
前台main.py对外开门：收你上传的书、接你的问题、还你答案
网页窗口ui.py前台门面，你在浏览器看到的聊天框
保安robustness.py哪坏了重试、兜底，不让系统崩
质检员judge.py出20道题考自己，AI 当裁判打分
⚠ 别找"ChromaDB 这个文件"——不存在，也不用建。
ChromaDB 是 pip 装进来的库（一个第三方包），代码里写 import chromadb 来用它，它不是你要写的 .py 文件。
它在你电脑上留下的"档案柜"实体，是跑完 ingest.py 后自动生成的 chroma_data\ 文件夹——里面的 chroma.sqlite3 存的就是那 3 条向量数据（该文件夹已被 .gitignore 排除，不会传 GitHub）。

③ 两条链路，大白话讲

入库链路 = 收书进柜（每份文档只走一次） 你上传一份 PDF → 收书员拆开 → 裁纸员切成小卡片 → 档案管理员把每张卡片抄两份（一份原文、一份"意思"编码）塞进档案柜 → 完事，书在柜里了。
上传文档 → loader.py 读文件（PDF/Word/TXT） → splitter.py 切成小块 → 智谱 embedding-2 算"意思"向量 → ingest.py 存进 ChromaDB
问答链路 = 客人找书（每次提问都走） 你问"RAG 是什么" → 前台转给检索员 → 检索员从档案柜两头翻：按意思（你问的"检索增强"，柜里有张卡片也是这意思）＋ 按关键词（"RAG"字母原文匹配）→ 找到最像的 5 张 → 抄写员把这 5 张塞给 DeepSeek → DeepSeek 只看着 5 张卡片答题 → 前台把答案还你，还附带"来源：第2本书第3页"。
用户提问 ↓ ui.py（网页）或 curl 发起 ↓ POST /api/ask FastAPI main.py 接收 ↓ 交给检索 retriever.py 双路召回： ① 向量路：问题→智谱embedding-2→ChromaDB 按"意思"查 ② 关键词路：jieba分词 + BM25 按"字面"查 ↓ 两路归一到0-1 → 加权融合 → 去重保序 → Top-k ↓（可选 reranker.py：粗找20条 → 精排top5） generator.py 拼Prompt：资料 + 问题 ↓ DeepSeek 生成（只根据资料回答，没有就说不知道） ↓ 返回 answer + sources（来源文件名+块号/页码） ↓ 界面显示答句下方列出来源

④ 三个关键考点（面试/被追问先背）

1️⃣ 为什么要切块？
整本书一次性塞给 AI：太长、塞不下、也不精准。切成小卡片，只挑跟问题最相关的几张，精准又省token（省钱）。
2️⃣ 为什么双路检索？
单靠"意思"找，遇到专业缩写（如 RAG）会抓瞎；单靠"关键词"找，换个说法就找不到。两路互补：意思近 + 字面像都捞上来，融合排序。
3️⃣ 为什么答案要带来源？
让 AI 照卡片答、不瞎编（防幻觉），出错了能顺着来源去核对原文——这是企业级系统跟"聊天机器人"的根本区别。

⑤ 别人问"你项目难点是什么"

"最难的是中文检索。英文按空格分词就行，中文得先用 jieba 分词（'向量数据库存向量'→'向量/数据库/存/向量'）。另外要控制答案不瞎编——我的做法是 prompt 里写死'只根据资料回答，资料里没有就说不知道'，并且返回来源让用户能核对。"
